# Audit sécurité et interactions — 31 octobre 2026

Base examinée : `673ab9ec7938d295a7a328bb969e281c033ba660`, après fusion de la
PR Busboy #8. Les corrections sont proposées sur une branche dédiée ; cet
audit ne déploie aucune modification sur une instance.

## Périmètre et méthode

- Audit du lockfile npm, dépendances de production et de développement.
- Revue ciblée des routes API : authentification, permissions, CSRF, uploads,
  livraison de médias, import de bundles et récupération des mises à jour.
- Revue de la séparation Caddy/API et des changements de compatibilité Fastify.
- Corrections des interactions du Studio et des espaces délégués ; tests Node
  et essais du module applicatif dans un DOM simulé, avec des données fictives.

L’exposition réseau réellement déployée et les paquets système des images
Docker n’ont pas été scannés. Le client Android n’a pas été recompilé dans
cette passe. Aucune conclusion d’absence globale de vulnérabilité n’en découle.

La CI vérifie également les dépendances de production au seuil `high`.

## Corrections applicatives de sécurité et de robustesse

1. **Adresse cliente derrière Caddy.** Fastify récent désactive `trustProxy: 1`.
   Une fonction vérifie désormais l’adresse du pair et refuse tout saut
   supplémentaire. Une liste `ROOMFRAME_TRUSTED_PROXY_CIDRS` permet de préciser
   les adresses de Caddy. Les valeurs de proxy présentées par un pair non admis
   sont ignorées. Les tests couvrent aussi une chaîne XFF falsifiée en amont.
2. **Upload média tronqué.** Le flux pouvait s’arrêter à la limite Busboy sans
   que la copie sur disque échoue. Le drapeau `truncated` est maintenant
   vérifié avant l’analyse et l’enregistrement : réponse 413, fichier temporaire
   supprimé et aucune écriture en base.
3. **Nombre d’entrées ZIP.** La somme des tailles décompressées ne borne pas
   le nombre d’entrées vides. L’import rejette les archives dépassant 4096
   entrées avant de collecter davantage de métadonnées. Cette borne laisse de
   la marge aux 1000 artefacts autorisés, aux fichiers de contrôle et aux dossiers.
4. **Multipart malformé.** Les erreurs précises de frontière manquante ou de
   flux incomplet renvoient 400 au lieu de 500. Les erreurs serveur ordinaires
   conservent leur traitement existant.

Les deux routes multipart conservent session, permission et CSRF avant parsing.
Les tests contrôlent ces refus, les caractères CR/LF et une frontière de 252
caractères fragmentée, sans envoyer de trafic à une instance réelle.

## Corrections UX et accessibilité des interactions

- Publier exige que le brouillon corresponde à la révision enregistrée. Le
  bouton et le statut annoncent les modifications à enregistrer.
- Une modification réalisée pendant l’enregistrement ne devient pas
  artificiellement « sauvegardée ». Une réponse destinée à une autre scène
  n’écrase pas la sélection courante.
- Une modification réalisée pendant une publication est conservée.
- Un échec réseau pendant un rechargement conserve le dernier brouillon.
- Les rôles Versions et Sécurité chargent leurs propres endpoints autorisés,
  sans demander le document Studio interdit. La navigation et les formulaires
  suivent les permissions ; une donnée inaccessible n’est plus présentée comme
  une liste vide. Le rôle Parc ne peut plus modifier localement la scène.
- Les erreurs courantes sont traduites en français, avec conservation du code
  technique dans `ApiError.code`. Les réponses 204 et `application/problem+json`
  sont gérées. Les erreurs serveur inconnues ne sont pas affichées telles quelles.
- La déconnexion protège un brouillon modifié, ne prétend pas avoir révoqué la
  session en cas d’échec réseau et recharge le document après révocation pour
  retirer les anciennes données et requêtes en cours du client.

## Vérification et limite visuelle

Commandes reproductibles :

```bash
cd services/api
npm ci
npm run check
npm test
npm audit --json
cd ../..
node --test prototype/admin/*.test.mjs prototype/tv/*.test.mjs
./scripts/check.sh
./scripts/test-supply-chain.sh
```

Sans PostgreSQL, `npm test` ignore explicitement le grand scénario
d’intégration. Le workflow `validate` exécute `scripts/test.sh` avec PostgreSQL
17, migrations et séparation des rôles. Son résultat doit être consulté pour
le commit proposé, et non déduit d’une ancienne exécution.

Les essais locaux supplémentaires dans un DOM simulé couvrent le démarrage des
rôles Propriétaire, Versions, Sécurité et Parc, l’édition pendant une sauvegarde
et la conservation du brouillon lors d’une panne réseau.

La capture dans le navigateur a été refusée par le contrôle automatique de
l’environnement. Il n’y a donc pas de nouvelle preuve visuelle acceptée :
contrastes, mise en page responsive, lecteur d’écran et comportement sur TV
restent à vérifier dans un navigateur et sur le matériel. Les corrections
ci-dessus concernent des comportements vérifiés dans le code et les tests,
pas une refonte visuelle prétendument validée.
